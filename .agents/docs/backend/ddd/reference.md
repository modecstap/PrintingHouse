# Справочник правил DDD

Требуемая форма. Код ей противоречит — верен этот файл. Зачем деление: [объяснение](explanation.md). Как добавить код: [инструкция](howto.md).

## Слои

Бизнес-логика описывает процессы, состояния и инварианты.

Инфраструктура: ORM-модели, SQL, HTTP DTO, контроллеры и обработчики, внедрение зависимостей, брокер сообщений, менеджер транзакций, логирование, кэш, клиенты внешних API.

| Слой | Что лежит |
| --- | --- |
| Бизнес | агрегат, entity, value object, команды, интерфейс репозитория |
| Сценарии | сервисы |
| Инфраструктура | HTTP, SQL, сборка зависимостей |

Бизнес-код не импортирует инфраструктуру. Обработчик вызывает сервис. Сервис вызывает агрегат через интерфейс репозитория. Реализацию репозитория передаёт сборка зависимостей.

## Агрегат

Основная единица бизнес-логики и транзакционная граница.

- Снаружи агрегат меняется только методом корня. Вызов метода вложенной части из сервиса запрещён.
- Поля — entity или value object. Примитив допустим только если за полем нет бизнес-правила.
- Поля открыты. Сервис может их читать. Писать в поля может только репозиторий, когда собирает объект из базы. В остальных местах присваивание поля запрещено. Компилятор это не проверяет.
- Агрегат небольшой.
- Другой агрегат хранится ссылкой по ID, не вложенным объектом.
- Есть поле `version`. По нему видно, синхронизирована ли локальная копия с базой.

## Entity

Объект со своим ID. Держит часть логики агрегата. Состояние entity меняет метод корня, не сервис.

## Value object

Вид объектов: деньги, адрес, email, период, телефон.

- Неизменяемый: после создания поля не меняются.
- Сравнивается по значению, не по ссылке.
- Всегда проверяет себя сам. Вызывающий это правило не копирует.
- Может содержать несколько полей.
- Один и тот же тип могут держать несколько entity.

Деньги не бывают `float` и не бывают примитивом.

## Репозиторий

К агрегату прилагается интерфейс. Он лежит рядом с агрегатом.

- `Save` возвращает ID агрегата. Этого ID в базе нет: insert. ID есть: update всех entity, которые принадлежат агрегату.
- `Take` возвращает агрегат целиком, со всеми entity, не часть.
- При `Save` репозиторий сравнивает `version` с базой. Версии совпали: запись проходит, `version` становится новой. Не совпали: ошибка, строка в базе не меняется.

Реализация содержит SQL и ORM и не содержит инвариантов агрегата.

## Сервис

Бизнес-код: инфраструктуру не импортирует.

- Принимает команду агрегата. Отдельный DTO сервиса командой не является.
- Описывает сценарий, который не помещается в один агрегат.
- Читает и пишет базу только через репозиторий.

Один агрегат: `Take`, метод корня, `Save`. Доменная ошибка: вернуть её, `Save` не вызывать.

Несколько агрегатов: `Take` каждого, метод каждого корня, `Save` каждого изменённого внутри одной транзакции инфраструктуры. Менеджер транзакций в сервисе не реализуется.

## Команда

Вход сценария. В ней нет обращения к базе и нет инварианта агрегата. Сервис передаёт её в метод корня.

## Цепочка вызова

HTTP, затем команда, затем сервис, затем `Take`, затем метод корня, затем `Save`, затем результат, затем HTTP.

Обработчик не вызывает агрегат и не пишет SQL. Агрегат не импортирует HTTP и инфраструктуру.

Чтение без изменения: `Take`, метод просмотра корня, без `Save`.
