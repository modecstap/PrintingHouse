# Как применять правила DDD

Шаги для нового кода. Форма: [справочник](reference.md). Зачем она такая: [объяснение](explanation.md). Текущий файл расходится со справочником — делай по справочнику.

## Новое действие агрегата

1. Добавь команду рядом с агрегатом. Поля команды — value object. Примитив оставляй только там, где нет правила.
2. Добавь метод на корень. Инвариант проверяй в агрегате.
3. Вложенную entity меняй из метода корня.
4. Поле агрегата не присваивай. Это разрешено только репозиторию при сборке из базы.
5. Тест вызывай через публичный метод корня.

## Новый value object

1. Тип положи рядом с агрегатом.
2. Проверку держит сам тип: конструктор или его метод отвергает недопустимое. Вызывающий правило не копирует.
3. После создания поля не меняй.
4. Сравнивай по значению.
5. Тот же тип можно вложить в разные entity. Деньги делай value object, не `float`.

## Метод сервиса для одного агрегата

1. Прими команду агрегата.
2. `Take` агрегата по ID из команды.
3. Вызови метод корня и передай команду.
4. Ошибка домена: верни её. `Save` не вызывай.
5. Успех: `Save`. Дальше используй ID, который вернул `Save`.
6. Поле агрегата не присваивай. Метод вложенной entity из сервиса не вызывай.

## Сценарий на несколько агрегатов

1. Одна команда описывает весь сценарий.
2. `Take` каждого агрегата по его ID.
3. У каждого вызови метод корня. Соседний агрегат в корень целиком не передавай.
4. Ошибка домена: не вызывай `Save`.
5. Успех: `Save` каждого изменённого агрегата одной транзакцией инфраструктуры. Менеджер транзакций в сервис и в агрегат не клади.

## HTTP-обработчик

1. Собери команду из DTO запроса.
2. Вызови метод сервиса. Агрегат и SQL из обработчика не вызывай.
3. Доменную ошибку переведи в ответ HTTP. Проверку инварианта в обработчик не копируй.
4. Результат сервиса переведи в DTO ответа.

## Репозиторий агрегата

1. Рядом с агрегатом объяви репозиторий: `Save` возвращает ID, `Take` возвращает целый агрегат.
2. Реализацию положи в инфраструктуру. SQL и ORM только там.
3. `Take` собирает все entity агрегата и заполняет поля, включая `version`.
4. `Save`: этого ID в базе нет — вставка всех entity; ID есть — обновление каждой entity агрегата. `version` не совпала — верни ошибку и базу не меняй. После записи верни ID агрегата.
5. Новое поле агрегата отображай в этой реализации. В метод агрегата SQL не добавляй.
6. Сборка зависимостей передаёт реализацию в сервис. Сервис зависит от интерфейса репозитория, не от инфраструктуры.
